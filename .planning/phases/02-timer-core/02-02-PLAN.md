<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| localStorage → app state | Stored timer record is fully untrusted on read (could be corrupted, stale schema, or hand-edited) |
| user input → DOM | Repeat number input crosses into validation and the cycle counter |
| backgrounded time → state | Wall-clock gap on return drives cycle catch-up math |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Severity | Mitigation Plan |
|-----------|----------|-----------|-------------|----------|-----------------|
| T-02-04 | Tampering | loadTimerState() reading localStorage | mitigate | medium | JSON.parse wrapped in try/catch; schemaVersion checked; any error/mismatch returns null → clean idle start. Acceptance criteria assert a `not-json` value loads without crashing. |
| T-02-05 | Tampering (XSS) | restored cycle counter / display / state label writes | mitigate | medium | All restored values rendered via `textContent`; numbers re-derived from parsed integers; no `innerHTML` of stored strings. Acceptance criteria assert no innerHTML of stored/parsed values. |
| T-02-06 | Tampering (input) | parseRepeat on Repeat field | mitigate | low | Integer-only validation; rejects 0/negative/non-integer/empty → inline message; covered by node:test. |
| T-02-07 | Denial of Service (self) | hand-edited cycleEnd causing huge negative remaining + runaway catch-up | mitigate | low | missedCycles is bounded by elapsed/duration and cycleIndex is clamped to the finite total; catch-up fires at most one beep. No unbounded loop. |
| T-02-SC | Tampering | npm/pip/cargo installs | n/a (accept) | none | No package installs — browser-native APIs + node:test (Node built-in). No third-party packages → no slopcheck gate required. |

No unmitigated HIGH-severity threats.
</threat_model>
